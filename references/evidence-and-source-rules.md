# 证据与来源规则

## 结论分类

每条重要结论必须落在下列一类，不得混用。

| 分类 | 含义 |
| --- | --- |
| 【事实】 | 来源能够直接支持 |
| 【推断】 | 根据事实做出的合理判断 |
| 【预测】 | 关于未来可能发展的情景 |
| 【建议】 | 针对用户情况的行动方案 |
| 【未知】 | 当前证据不足，无法确定 |

预测不得写成事实，个人判断不得包装成统计结论。

## 来源优先顺序

1. 政府部门、统计机构与公共就业服务平台，含人社部门职业分类与职业标准、国家统计局、中国就业网、地方人社部门。
2. 企业官方招聘信息与岗位说明。
3. 正规招聘平台的岗位与薪资样本。
4. 行业协会、研究机构、高校就业报告。
5. 国际劳工组织、经合组织等机构研究。
6. 从业者访谈、专业社区与技术论坛的一手经验。

## 来源等级

每条来源除核验状态外，再标一个等级。等级判断证据本身，不判断机构名气。

| 等级 | 含义 |
| --- | --- |
| A | 官方统计、职业标准、监管文件、企业原始招聘页或可复核原始数据 |
| B | 有明确样本与口径的行业报告、研究机构报告、高校就业报告 |
| C | 招聘平台样本、从业者访谈、专业社区经验；可作线索，需交叉验证 |
| D | 匿名帖子、二手转述、无法复核或来源不明的内容；只作假设 |

## 证据门槛

- 薪资、招聘需求、入行门槛、AI 替代等高风险结论，至少两个相互独立的 A 或 B 级来源，或一个 A 级来源加一个可复核样本。
- 只有一个 C 级来源时，结论标为【推断】或【未知】，不得写成【事实】。
- 只有一个 D 级来源时，只用于生成待验证问题。
- 来源冲突时并列保留，先比较地区、年份、样本、口径与企业类型，再做判断。

## 每条来源的必备字段

- 来源类型；
- 标题；
- 发布机构或作者；
- 原始 URL；
- 发布日期；
- 访问日期；
- 覆盖地区；
- 统计口径或样本说明；
- 来源等级：A / B / C / D；
- 样本量：数量与范围，没有样本概念时写「不适用」；
- 它支持的具体结论；
- 可信度与限制；
- 关键摘录：只保留判断所需的最小片段；
- 核验状态：已核验 / 部分核验 / 待核验 / 已失效；
- 替代链接：没有时写「无」。

无法获得 URL 或日期时，明确写出缺失原因，不得留空假填。

项目内保留证据索引与必要短摘录，不保存整站、全量数据库或大规模受版权保护内容。登录、付费或平台限制内容只记录元数据、结论与限制，不绕过访问控制。

## 硬性禁止

- 不编造招聘数量、薪资、工作时间、行业趋势或 AI 替代数据。
- 不把招聘平台职位数当成整个就业市场的岗位数量。平台数据可能有重复、失效、长期挂岗与口径差异。
- 不把单个从业者收入当成职业普遍收入。
- 不把少数高薪案例当成普遍水平。
- 只有招聘广告薪资时，必须声明它不是实际到手工资的统计分布。
- 不选择性引用。多来源冲突时说明差异与可能原因。
- 不把企业宣布采用 AI 等同于已经裁员。

## 收入口径

必须区分税前工资、税后收入、营业额与经营利润。受雇岗位与自主经营路线不得直接比较营收与工资。收入尽量区分：应届生或新人、3 至 5 年经验、资深；固定工资与绩效、提成、奖金、津贴；地区与企业类型差异。

## 无联网或检索失败时的处理

1. 明确说明当前无法完成实时核查。
2. 把需要补充的证据写入该职业的「证据缺口」与项目状态文件的待办。
3. 只使用用户提供的资料和已保存的本地来源，并标注其时间与来源。
4. 不伪装成已经检索过网页。
5. 不因缺少检索能力而编造结论；可以继续完成不依赖外部检索的部分。

## 来源核验状态

- 已核验：原始页面、发布日期、口径与支持结论均已确认。
- 部分核验：页面存在，但发布日期、样本或原始数据不完整。
- 待核验：目前只有二手线索或无法打开原页。
- 已失效：原链接不可用；保留历史记录并寻找替代链接。

GitHub 仓库在 README、数据文件、许可、字段、更新时间和来源口径完成核验前，只能标记为线索，不得当成职业事实。

## 动态信息

涉及招聘、薪资、技术变化的信息必须注明数据年份与访问日期。过期数据要标注时效限制。

薪资、招聘数量、岗位趋势超过 18 个月未更新时，标记「时效受限」，不得直接当作当前事实；不能补充新证据时按【未知】处理。
