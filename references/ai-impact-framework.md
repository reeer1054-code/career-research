# AI 职业影响框架

用于 AI 影响支持流程。核心要求：按具体任务分析，不按职业名称贴标签。

## 四类影响

每个职业必须分别判断，不能笼统写「既有机遇也有挑战」。

1. 任务自动化：AI 可直接完成原本由人完成的某些任务。
2. 岗位生产率提升：一个人用 AI 完成过去需要多人完成的工作。就业影响需结合实际证据判断，不能默认等于裁员。
3. 岗位结构改变：职业名称保留，但工作内容、技能要求与人员配置变化。
4. 新需求与新职业：AI 降低某些工作的成本，使过去不经济的业务可行，或产生新的工作任务。

## 分析步骤

1. 把职业拆成具体任务。
2. 逐项判断该任务当前能否被 AI 直接完成、能否被 AI 显著加速、是否仍需人工审核。
3. 检查是否涉及复杂现实环境、责任承担、组织协调、人际信任或现场操作。
4. 区分已观察到的企业变化与预测。
5. 单独研究新人岗位：企业是否减少初级招聘、培养型任务是否减少、企业对新人使用 AI 独立完成任务的要求是否提高、入行门槛是否因此升高。
6. 输出转型路线，但每条路线都要核查实际招聘需求、技能重合度、学习成本与收入变化。

## 采用证据

判断企业是否已改变流程或人员配置时，优先找下列证据，并写清年份、地区、企业与样本：

- 招聘岗位数量与构成随时间的变化；
- 岗位职责与技能要求的变化；
- 企业年报、招股书或公开访谈中的流程与人员变化；
- 行业研究中的企业采用率、使用成本、准确率与责任风险；
- 从业者提供的工作流变化，但只作补充线索。

模型演示、厂商宣传和单一企业案例只能证明技术可能性，不能证明行业已大规模替代人工。来源入口见
[source-catalog.md](source-catalog.md) 的「AI 与劳动力市场来源」。

## 影响卡

每个职业输出一张影响卡，共九项。

| 指标 | 判断内容 |
| --- | --- |
| 当前任务暴露程度 | 目前有多少工作任务可被 AI 直接执行或显著加速 |
| 岗位替代风险 | 企业未来是否可能因自动化减少该岗位需求 |
| 工作内容变化程度 | 核心工作可能发生多大变化 |
| AI 增强机会 | 使用 AI 后能否获得更高生产率或更强竞争力 |
| 新需求潜力 | AI 是否可能创造新的业务需求与岗位 |
| 现实证据 | 是否已观察到流程、招聘或人员配置变化 |
| 时间不确定性 | 变化时间与幅度的不确定性 |
| 个人适应成本 | 用户适应变化所需的学习投入 |
| 新人就业与初级岗位风险 | AI 对入门岗位数量的影响 |

判断用低、中、高或明确区间，并写出依据。

硬性约束：

- 不得把 AI 暴露程度直接等同于失业概率。
- 不得把「需要人际沟通」直接等同于「不会被替代」。
- 不得只凭模型演示推断企业已能大规模替代人工。
- 不得把企业宣布采用 AI 等同于已经裁员或替代。
- 必须考虑企业采用动力、使用成本、准确率、责任风险、客户接受度和真实业务流程。

## 三种情景

对重要职业分析未来 5 至 10 年情景。三种情景都是分析工具，不是确定预言。

- 保守情景：AI 能力提升较慢，企业采用受成本、监管、可靠性限制。
- 中性情景：AI 持续进步，企业逐步整合工具，部分任务自动化，岗位要求变化。
- 激进情景：AI 能力和可靠性显著提高，企业工作流深度重构，更多任务可自动完成。

每种情景都要写明：成立条件、关键驱动因素、可能被自动化的任务、可能被压缩的岗位、可能出现的新工作内容、对新人就业的影响、从业者需要的能力、对该职业选择意味着什么。

没有可靠证据时，不得声称某职业将在某个确定年份消失。

## 细分岗位差异

同一职业名称下的细分方向影响差异很大，必须分开分析。例如翻译要区分普通笔译、专业技术翻译、法律与合规翻译、本地化项目管理、机器翻译质量评估与后期编辑；软件开发要区分简单代码编写、复杂系统设计、遗留系统维护、测试、架构、业务分析与生产故障处理。
